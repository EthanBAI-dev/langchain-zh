## 开始之前：环境到底是什么？

刚接触编程时，很容易产生一个疑问：代码文件明明已经在电脑里，为什么还不能直接运行？

因为代码只是写给计算机看的“说明书”。要真正执行它，还需要解释代码的程序、代码依赖的工具包，以及运行时使用的配置。这一整套东西，合起来就叫做**开发环境**。

在这门课里，可以先把环境理解成下面五层：

```text
VS Code                 编辑代码
   ↓
Python 3.12             读取并执行 .py 文件
   ↓
.venv 虚拟环境           隔离这门课使用的 Python 和工具包
   ↓
LangChain / LangGraph   课程代码依赖的工具包
   ↓
.env                    可选：保存 API Key 等私密配置
```

- **VS Code** 是编辑器，负责打开、修改和调试代码，本身不是 Python。
- **Python** 是解释器，负责逐行执行 `.py` 文件。
- **工具包**是别人写好的功能，例如 LangChain、LangGraph 和 pytest。
- **虚拟环境**是项目自己的工具箱，通常放在 `.venv` 目录里。
- **环境变量**是程序运行时读取的配置；API Key 通常保存在 `.env` 文件中。

### 为什么每个项目要有自己的虚拟环境？

假设项目 A 需要某个工具包的 1.0 版本，项目 B 需要 2.0 版本。如果所有项目共用同一套工具包，升级 B 可能会让 A 突然不能运行。

`.venv` 相当于给当前课程准备一个独立工具箱：我们在里面固定 Python 和依赖版本，不影响电脑里的其他项目。删除 `.venv` 不会删除你的代码；重新安装依赖，就能再建一个相同的环境。

### “当前目录”为什么重要？

终端中的命令总是在某个目录下执行。很多工具会从**当前目录**寻找配置文件：pytest 寻找测试，Python 寻找模块，`langgraph dev` 寻找 `langgraph.json`。

在 PowerShell 中可以运行下面的命令查看自己在哪里：

```powershell
Get-Location
```

因此，“命令正确但目录不对”仍然会报错。后面的每条命令都会明确写出应该在哪个目录执行。

## 0.1 现在真正需要准备什么？

先只准备能完成离线练习的最小环境。API Key、Jupyter 和 Studio 都可以以后再加。

| 项目 | 现在是否需要 | 它负责什么 |
|---|---:|---|
| VS Code | 需要 | 阅读、编辑和调试代码 |
| Python 3.12 | 需要 | 执行课程中的 Python 代码 |
| uv | 需要 | 创建 `.venv` 并安装依赖 |
| Git | 下载仓库时需要 | 从 GitHub 下载和更新课程代码 |
| 模型 API Key | 暂时不需要 | 调用 OpenAI、Anthropic、Google 等在线模型 |
| LangSmith API Key | 暂时不需要 | 在线记录和分析 Agent 的运行过程 |
| Tavily API Key | 暂时不需要 | 在后续章节让 Agent 搜索网页 |

这套教程的自动检查使用离线假模型，所以即使没有任何账号或 API Key，也能完成基础练习。

## 0.3 在 VS Code 中手动建立课程环境

下面的命令都在仓库根目录执行，也就是包含 `content`、`exercises` 和 `site` 的 `langchain-zh` 目录。

### 第 1 步：下载仓库

如果你已经打开了本项目，可以跳过这一步。

```powershell
git clone https://github.com/EthanBAI-dev/langchain-zh.git
cd langchain-zh
```

### 第 2 步：安装 uv

Windows PowerShell：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

macOS / Linux：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装完成后，关闭并重新打开终端，然后检查：

```powershell
uv --version
```

只要能看到版本号，就说明 uv 可以使用。

### 第 3 步：创建虚拟环境并安装依赖

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv -r exercises/requirements.txt -r exercises-langgraph/requirements.txt
```

第一条命令创建 `.venv`；第二条命令把课程需要的工具包装进去。以后不需要每次重新安装，只要 `.venv` 还在就可以继续使用。

### 第 4 步：让 VS Code 使用 `.venv`

1. 按 `Ctrl+Shift+P` 打开命令面板。
2. 输入并选择 `Python: Select Interpreter`。
3. 选择项目中的 `.venv`；Windows 下通常显示为 `.venv\Scripts\python.exe`。

这一步是在告诉 VS Code：“运行代码时，请使用课程自己的 Python，而不是电脑里其他 Python。”

## 0.4 跑通第一条检查

Windows PowerShell：

```powershell
cd exercises
..\.venv\Scripts\python.exe -m pytest ch00_setup -k versions
```

macOS / Linux：

```bash
cd exercises
../.venv/bin/python -m pytest ch00_setup -k versions
```

成功时会看到类似输出：

```text
1 passed, 2 deselected
```

- `1 passed`：版本检查通过，说明 Python 和依赖已经能正常工作。
- `2 deselected`：因为命令中的 `-k versions` 只选择了版本题，另外两题暂时没有运行；这不是错误。

如果终端前面显示 `(base)`，说明 Conda 的基础环境也处于激活状态。这里使用了 `.venv` 中 Python 的完整路径，所以课程检查仍会使用正确的环境。

## 0.5 什么时候才需要 `.env` 和 API Key？

只有在你准备调用真实在线模型时，才需要 API Key。

| 运行方式 | 是否联网 | 是否需要 API Key | 是否产生模型费用 |
|---|---:|---:|---:|
| pytest 自动检查 | 否 | 否 | 否 |
| 练习自带的离线假模型 | 否 | 否 | 否 |
| OpenAI、Anthropic、Google 等真实模型 | 是 | 是 | 可能会 |

需要真实模型时，从仓库根目录复制模板：

```powershell
Copy-Item exercises\.env.example exercises\.env
```

然后在 `exercises/.env` 中填写模型名称和对应的 Key。例如使用 OpenAI 时，还需要安装模型厂商的适配包：

```powershell
uv pip install --python .venv langchain-openai
```

```dotenv
LC_MODEL=openai:gpt-5-mini
OPENAI_API_KEY=填写你自己的Key
```

`.env` 是私密文件，不要截图分享，也不要提交到 GitHub。课程已经将它加入 `.gitignore`。

## 0.6 为什么现在不启动 Jupyter 和 Studio？

本教程的练习是普通 `.py` 文件，直接在 VS Code 中运行即可，因此 Jupyter 不是入门必需品。

LangSmith Studio 是后面观察 LangGraph 节点和状态的可视化调试器。`langgraph dev` 启动时会在当前目录寻找 `langgraph.json`；而 `exercises` 根目录没有这个文件，所以在那里运行一定会报错：

```text
Invalid value for '--config': Path 'langgraph.json' does not exist.
```

这不代表环境坏了，只代表当前目录不是一个可启动的 LangGraph 项目。等学到对应章节、目录中已经生成 `langgraph.json` 后，再启动 Studio。
